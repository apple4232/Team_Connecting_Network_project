# 실제 Solar 조기 종료 진단과 복구

2026년 11월 24일 로컬 TCP 파일 전송에서 얻은 실제 Solar 응답과 실행 기록입니다. 기본 파일 크기는 4,194,304 B이며 연결 중단 위치는 1,398,101 B입니다. 모델 별칭은 `solar-pro4`, 반환된 모델 ID는 `solar-pro4-260806`입니다.

## 확인 결과

`solar_demo_summary.json`의 실행 ID는 `run-20261124T113327894315-01`입니다. 실제 전략 요청·응답을 확인했고, Solar의 `resume` 제안을 Python이 적용했습니다. 파일 크기와 SHA-256 검증, 장애 시나리오 재현이 모두 성공했습니다. `solar.json`에서 진단 `early_connection_close`, 정답 일치, 근거 ID 존재, 근거 지지를 확인할 수 있습니다. 패킷 캡처는 요청하지 않았으며 사후 진단에는 앱 관측 로그를 사용했습니다.

| 파일 | 내용 |
|---|---|
| `solar_demo_summary.json` | 전략 적용·전송·통합 검증 요약 |
| `run_meta.json` | 장애 조건과 재현·전송 검증 결과 |
| `logs/client.jsonl` | 실제 전략 요청·응답, 최종 적용, 재접속과 전송 검증 |
| `logs/server.jsonl` | 연결과 송신 바이트 기록 |
| `logs/injection.jsonl` | 팀 평가용 장애 주입 정답 기록 |
| `evidence.jsonl` | 사후 진단에 제공한 관측 이벤트 |
| `request.json` | 실제 사후 진단 요청 본문 |
| `response_raw.json` | 실제 응답, 요청 ID, 모델과 토큰 사용량 |
| `rule.json` 및 `solar.json` | 규칙 기반 진단과 실제 Solar 채점 결과 |
| `comparison.csv` | 두 방식과 전송 검증 결과의 비교표 |

주입 기록과 `run_meta.json`의 정답 라벨은 진단 입력에서 제외됩니다. 요청 파일에는 API 요청 본문을 기록하며 인증 헤더와 키는 기록하지 않습니다. 로컬 파일 경로와 실행 시각은 원래 로그에 포함됩니다.

## 앞선 오판 기록

`before_prompt_update` 폴더는 실행 `run-20261124T113137468384-01`의 원래 자료입니다. 복구 전략 적용과 해시 검증은 성공했으나 Solar가 완료 이벤트 `E016`과 해시 검증 `E019`만 인용해 `no_failure_observed`로 판정했습니다. `E008`에 조기 연결 중단이 존재하므로 정답·근거 지지 평가는 실패했습니다.

이후 지침에 전체 관측 구간의 중단을 진단하고, 복구 이후의 성공은 복구 결과로 해석하도록 명시했습니다. 두 폴더는 지침이 다른 개별 실행의 결과이며, 같은 입력에 대한 반복 성능 비교는 추가 실험이 필요합니다. 각 폴더의 `request.json`으로 사용한 지침을 확인할 수 있습니다.

## 다시 실행하기

`Demo V4/First Demo`에서 `python solar_demo.py`를 실행합니다. 키가 환경 변수에 없으면 가려진 입력창이 표시됩니다. 기본 사례는 전략 제안과 사후 진단으로 실제 API를 두 번 요청합니다. 실행 결과 폴더는 터미널에 출력됩니다. 이 샘플의 로그와 프레임 번호 등은 해당 실행에만 적용됩니다.
